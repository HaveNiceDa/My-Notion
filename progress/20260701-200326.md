# 2026-07-01 AI 服务计费防护

## 目标

针对阿里云百炼异常欠费排查结果，收紧 My-Notion AI 调用链路，避免请求体透传未知模型或公开服务继续消耗 DashScope API Key。

## 已完成

- 在 `packages/ai/config/model.ts` 增加模型白名单校验，未知模型不再原样透传到上游。
- Web AI 路由 `/api/chat`、`/api/rag`、`/api/agent/stream`、`/api/editor-ai/streamText` 改为使用白名单解析模型，非法模型返回 400。
- 独立 `services/ai` 的 Vercel Edge route 与 Hono 服务增加 `AI_SERVICE_AUTH_TOKEN` 鉴权、基础限流和模型白名单。
- `services/ai/.env.example` 增加 `AI_SERVICE_AUTH_TOKEN` 与 `AI_SERVICE_ALLOWED_ORIGINS` 配置项。
- 补充配置单测，覆盖未知模型拒绝逻辑。

## 风险与后续

- 部署 `services/ai` 前必须配置新的 `AI_SERVICE_AUTH_TOKEN`；未配置时服务会拒绝非 health 请求。
- 如果移动端未来直接调用 `services/ai`，不能把共享 token 放进 `EXPO_PUBLIC_*`；应优先经 Web API 走 Clerk 鉴权，或为服务补 Clerk JWT 校验。
- 建议继续在阿里云侧设置百炼消费额度/告警，作为代码防护之外的兜底。
