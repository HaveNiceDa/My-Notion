# 编辑器 AI 选区状态与工具调用修复

## 目标

修复 Web 编辑器中选中文字后使用 AI 指令时，后端虽然收到 `metadata.documentState`，但模型仍返回纯文本询问“需要翻译哪部分内容”，导致 BlockNote AI 前端无可执行文档操作的问题。

## 完成变更

- 将 `packages/ai/server/editor-ai/inject-document-state.ts` 的文档状态注入方式从独立 assistant 消息调整为当前 user message 前缀，确保选区内容和用户指令在同一轮输入中绑定。
- 在 `apps/web/src/app/api/editor-ai/streamText/route.ts` 中，有 BlockNote tool definitions 时显式设置 `tool_choice: "required"`，避免模型返回纯文本导致前端无操作可执行。
- 编辑器 AI 请求显式设置 `enable_thinking: false`，规避 DashScope thinking 模式与 `tool_choice` 的兼容风险。
- 新增 `packages/ai/__tests__/editor-ai-message-transform.test.ts`，覆盖选区状态合并到 user message 的转换行为。

## 已知风险

- `tool_choice: "required"` 依赖 DashScope 对当前非 thinking 编辑器模型的兼容性；已显式关闭 `enable_thinking` 降低冲突概率。
- 尚未做浏览器端手动回归，需要在本地页面复测“翻译成英文”等选区编辑指令是否返回 `applyDocumentOperations`。

## 下一步

- 本地刷新 Web 页面后重试选区 AI，检查 `/api/editor-ai/streamText` 是否输出 `tool-input-available` 而不是纯 `text-delta`。
- 后续可继续拆分 editor-ai route，把消息转换、tool choice 和流式写入抽为独立模块。
